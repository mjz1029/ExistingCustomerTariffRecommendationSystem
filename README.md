# 存量用户套餐推荐系统

> ExistingCustomerTariffRecommendationSystem

面向中国移动存量用户运营场景的全栈推荐系统，用于批量导入用户清单、维护套餐目录、执行智能套餐推荐，并输出推荐结果、人工校正结论与营销话术，帮助一线营销人员高效完成外呼回访工作。

## 功能特性

- **套餐目录管理**：内置中国移动 5G 套餐体系（畅享个人版 / 全家享爱家版 / 全光版 / 竞争应对资费），支持 Excel 全量导入、新增、编辑、删除、上下架
- **用户数据导入**：Excel 批量导入用户清单，自动解析中文字段映射与数据校验，支持异网用户竞品资费录入
- **智能推荐引擎**：基于规则的多维度评分算法，融合客户价值分层、超套严重度分级、消费弹性信号等 7 个优化维度，输出主推荐 + 最多 3 个备选方案
- **分析看板**：统计卡片（总用户数 / 高风险 / 待确认）、套餐分布饼图、按地区筛选、按手机号/套餐搜索、**标签拖拽筛选**（支持按客户类型/运营商/宽带状态/套餐状态/客户标签/审核状态/风险等级多维交叉过滤）
- **人工校正**：支持从全部在售套餐中手动改选最终方案，填写备注，设置审核状态（待确认 / 已接受 / 已驳回），改选后自动重算话术与风险
- **AI 营销话术**：支持配置 OpenAI / Anthropic / 兼容网关，基于用户画像与推荐结果生成 120-180 字的自然语言营销话术
- **对比分析**：用户详情页展示当前套餐与推荐套餐的全维度对比（月资费含搭载、近三月 ARPU、流量、语音、宽带、FTTR、搭载业务、办理条件），带差值箭头标注
- **结果导出**：导出包含推荐结果、人工校正、审核状态、AI 话术的完整 Excel 报表

## 使用流程

1. **套餐管理**：进入"套餐管理"页面，确认当前套餐数据是否准确，或通过 Excel 模板批量导入
2. **下载模板**：进入"数据导入"页面，下载用户清单标准模板
3. **导入数据**：按模板格式整理用户清单并上传 Excel 文件
4. **自动推荐**：系统自动解析数据并运行推荐引擎
5. **查看结果**：在"分析看板"查看批量结果，支持按地区筛选、按手机号/套餐搜索、标签拖拽筛选（客户类型/运营商/宽带状态/套餐状态/审核状态/风险等级等多维交叉过滤）
6. **人工校正**：进入用户详情页，查看推荐理由、风险等级、搭载要求、营销话术，手动改选方案或设置审核状态
7. **AI 话术**（可选）：在"AI 设置"中配置 AI 提供商后，可在用户详情页一键生成 AI 营销话术
8. **导出结果**：返回看板导出最终确认版 Excel 报表

## 推荐引擎逻辑

推荐引擎的核心文件为 `backend/app/services/engine.py`，采用基于规则的多维度加权评分算法。以下为完整的推荐流程：

### 流程概览

```
用户数据导入
    ↓
① 数据归一化（normalize_user）
    ↓
② 饱和度估算（estimate_saturation）
    ↓
③ 用户分群（infer_user_segment）→ mobile / broadband / fttr
    ↓
④ 运营商筛选（filter_plans_by_carrier）
    ↓
⑤ 分群匹配 + 宽带保留 + 不降档 过滤
    ↓
⑥ 预算计算（compute_budgets）→ 软预算 / 硬预算
    ↓
⑦ 资源目标值计算（get_resource_targets）
    ↓
⑧ 多维度加权评分（get_candidate_score）
    ↓
⑨ 四桶分级排序 → 主推荐 + 备选方案
    ↓
⑩ 结果构建 → 推荐理由 + 风险等级 + 营销话术
```

### 第①步：数据归一化（normalize_user）

将不同格式的原始数据统一为标准结构：

- **数值标准化**：确保资费、流量、通话等指标非负，饱和度约束在 0-1 区间
- **缺失值填充**：未标注宽带/FTTR 状态默认为 False，未标注运营商默认为"移动"
- **异常值修正**：NaN 替换为默认值，空字符串/"-" 视为空值

### 第②步：饱和度估算（estimate_saturation）

当用户数据中饱和度字段缺失（为 0）时，系统自动根据用户的 DOU/MOU 和当前套餐额度反推：

```
流量饱和度 = 用户月均流量 ÷ 当前套餐流量额度
语音饱和度 = 用户月均通话 ÷ 当前套餐通话额度
```

系统会从套餐目录中精确匹配或模糊匹配用户当前套餐，获取套餐的流量/通话额度。

### 第③步：用户分群（infer_user_segment）

将用户归入三个分群之一，决定后续候选套餐的筛选范围：

| 判定条件 | 分群结果 |
|----------|----------|
| `isFTTR=True` 或套餐名含"FTTR"/"全光" | fttr |
| `hasBroadband=True` 或套餐名含"全家"/"爱家"/"宽带" | broadband |
| 其余 | mobile |

采用"标识字段优先 + 套餐名称辅助"的双重判断机制，避免因数据不完整导致误判。

### 第④步：运营商筛选（filter_plans_by_carrier）

| 用户运营商 | 筛选规则 |
|------------|----------|
| 移动 | 排除竞品资费（`target_carrier=competitor`）和仅新入网资费（`mobile_only`） |
| 电信 / 联通 | 仅推荐竞争应对资费（`target_carrier=competitor`） |

异网用户填写了竞品资费信息时，系统以竞品价格为基准进行匹配。

### 第⑤步：候选池过滤

对分群后的候选套餐执行三重过滤：

1. **分群匹配**：fttr 用户 → 含 FTTR 的套餐；broadband 用户 → 含宽带的套餐；mobile 用户 → 纯移动套餐
2. **宽带保留**：已有宽带的用户，候选套餐宽带速率必须 ≥ 当前宽带速率
3. **不降档**：候选套餐月费总额（含搭载）≥ 当前有效价格

### 第⑥步：预算计算（compute_budgets）

采用"软预算 + 硬预算"双层控制机制：

```
有效ARPU = max(折后ARPU, 折前ARPU)
缓冲值 = 超套用户 10元，非超套 5元
行为预算 = max(当前价格, 有效ARPU + 缓冲值)

// 消费弹性调整
if 超消金 > 30元:  行为预算 += min(超消金 × 0.3, 20)
if 结余 > 100元:   行为预算 += 5

软预算 = max(当前价格, min(行为预算, 当前价格 + 跳档上限))
硬预算 = max(软预算, 当前价格 + 跳档上限 + 20)
```

优先在软预算范围内推荐，无合适方案时放宽到硬预算。

#### 跳档幅度控制（get_price_jump_cap）

跳档上限根据分群、当前档位、超套严重度、客户标签动态计算：

| 基础条件 | 跳档上限 |
|----------|----------|
| FTTR 用户 | 60 |
| 宽带用户（档位 < 79） | 30 |
| 宽带用户（档位 ≥ 79） | 40 |
| 移动用户（档位 < 29） | 30 |
| 移动用户（29 ≤ 档位 < 59） | 25 |
| 移动用户（59 ≤ 档位 < 99） | 30 |
| 移动用户（档位 ≥ 99） | 40 |

**动态调整（叠加）**：

| 信号 | 调整量 | 说明 |
|------|--------|------|
| 慢性超套（超套≥30元，或超套>0且饱和度≥80%） | +15 | 强升级需求，大幅放宽 |
| 轻度超套（有超套但未达慢性标准） | +5 | 小幅放宽 |
| 高饱和（流量饱和度≥90%，未超套） | +8 | 接近超套 |
| 语音高饱和（≥90%） | +5 | 通话紧张 |
| 零合约用户 | +5 | 无合约约束，可自由迁转 |
| 老旧套餐用户 | +8 | 老旧套餐是强升级目标 |

### 第⑦步：资源目标值计算（get_resource_targets）

根据超套严重程度确定推荐的资源目标：

| 超套分级 | 流量目标 | 语音目标 |
|----------|----------|----------|
| 慢性超套 | 实际用量 × 110% | 实际用量 × 110%（语音饱和≥75%时） |
| 轻度超套 | 实际用量 × 105% | 实际用量 × 105%（语音饱和≥90%时） |
| 无超套 | 实际用量 × 105%（流量饱和≥90%时） | 实际用量 × 105%（语音饱和≥90%时） |

目标上浮确保推荐套餐能覆盖用户实际需求并留有余量。

### 第⑧步：多维度加权评分（get_candidate_score）

对每个候选套餐计算综合得分（负分制，越接近 0 越优）：

```
score = -(
    价格差   × 价格权重
  + 流量缺口 × 60
  + 语音缺口 × 0.6
  + 流量浪费 × 0.5
  + 语音浪费 × 0.03
  + 带宽浪费 × 0.02
)
```

各维度说明：

| 维度 | 计算方式 | 权重 | 设计意图 |
|------|----------|------|----------|
| 价格差 | max(0, 套餐月费 - 当前价格) | 按客户分层（见下表） | 价格跨度不宜过大 |
| 流量缺口 | max(0, 流量目标 - 套餐流量) | 60 | **最高权重**，推荐必须够用 |
| 语音缺口 | max(0, 语音目标 - 套餐通话) | 0.6 | 确保通话基本满足 |
| 流量浪费 | max(0, 套餐流量 - 流量目标) | 0.5 | 惩罚过度推荐 |
| 语音浪费 | max(0, 套餐通话 - 语音目标) | 0.03 | 轻微惩罚 |
| 带宽浪费 | max(0, 套餐宽带速率 - 用户当前宽带) | 0.02 | 仅宽带用户 |

**价格权重按客户价值分层**（`get_customer_value_tier`）：

| 客户分层 | 判定条件 | 价格权重 | 说明 |
|----------|----------|----------|------|
| premium | 全球通/拍照中高端/ARPU≥128 | 8 | 高价值客户对价格不敏感 |
| standard | 其余 | 12 | 标准权重 |
| basic | ARPU<59 或老旧套餐 | 16 | 价格敏感客户，价格惩罚加重 |

### 第⑨步：四桶分级排序

将候选套餐按"预算范围 + 资源覆盖"分为四个优先级桶：

| 桶 | 条件 | 优先级 |
|----|------|--------|
| 0 | 软预算内 + 流量语音均覆盖 | 最优 |
| 1 | 硬预算内 + 流量语音均覆盖 | 次优 |
| 2 | 软预算内 + 资源未完全覆盖 | 可接受 |
| 3 | 硬预算内 + 资源未完全覆盖 | 兜底 |

排序规则：先按桶号升序，同桶内按评分降序，再按月费升序。

### 第⑩步：结果构建

#### 推荐理由自动生成

系统根据推荐逻辑自动组合中文推荐理由：

| 触发条件 | 推荐理由 |
|----------|----------|
| 价格高于当前 | 小幅提档 |
| 价格等于当前 | 同档位优化 |
| 低于最低可售 | 衔接最低可售档位 |
| 桶 ≥ 2 | 当前预算内就近匹配 |
| 流量覆盖 + 高饱和/超套 | 缓解流量超套 |
| 语音覆盖 + 高饱和 | 缓解通话紧张 |
| 宽带提速 | 宽带提速 / 保留宽带权益 |
| 新增宽带 | 新增宽带权益 |
| FTTR 保留/新增 | 保留FTTR权益 / 升级全光WiFi |
| 老旧套餐 + 价格提升 | 套餐焕新 |
| 零合约 | 无合约约束可灵活变更 |
| 资源未覆盖 | 注意:资源可能不足 |

#### 风险等级评估

| 等级 | 条件 |
|------|------|
| 低风险 | 资源完全覆盖，桶=0 |
| 中风险 | 桶 > 0 或推荐月费 > ARPU + 15 |
| 高风险 | 流量或语音未完全覆盖 |

#### 营销话术自动生成

根据用户类型（本网/异网）、费用变化、资源提升、宽带变化、FTTR 变化自动组合话术要素，120-180 字，口语化，以"您看可以帮您办理吗？"结尾。
